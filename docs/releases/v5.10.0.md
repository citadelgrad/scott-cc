# v5.10.0 — Beads skill pins bd 1.3.1

## Release scope

Published from `main`. This release changes the bd version that the Beads skill requires.

**Beads advanced-runtime release remains REJECT (`release_eligible=false`).** Packaging verification is not runtime promotion. No model-backed release evaluation was rerun and no default agent profile was promoted.

## Breaking change

The Beads skill now requires **bd 1.3.1** (#13). With bd 1.2.2 or another version, guarded operations fail closed with `UNSUPPORTED_BD_VERSION`. Upgrade bd before you upgrade this plugin (for example, `brew upgrade beads`). To stay on bd 1.2.2, pin v5.9.0.

## Changes

- `safe_bd.py` pins bd 1.3.1, with new help-contract hashes for all 15 commands and the upstream v1.3.1 commit `c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c`.
- The fail-closed output decoder accepts the new bd 1.3.1 issue fields, each with an exact type: `revision` (signed int64 decimal string), `lease_expires_at`, `heartbeat_at`, `comments_omitted`, `schema_version`.
- The skill references now describe bd 1.3.1 behavior:
  - Claims are leases. A supervisor can revert an expired claim with `bd reclaim`.
  - `bd sync` exists, but it is not an approved profile.
  - The `--if-assignee` and `--if-status` update guards exist, but the skill does not use them yet.

## Known limitations

- The skill does not call `bd heartbeat`. A long task can lose its claim if a supervisor runs `bd reclaim`.
- In bd 1.3.1, `dolt-auto-commit` is on by default.
- The new bd issue types `spike`, `story` and `milestone` are not accepted for create.
