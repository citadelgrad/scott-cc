# v5.11.0 — pas-pipeline skill targets PAS 0.11.1

## Release scope

Published from `main`. This release updates the `pas-pipeline` skill for PAS 0.11.1 (tag `v0.11.1`, commit `b82172d`).

**Beads advanced-runtime release remains REJECT (`release_eligible=false`).** Packaging verification is not runtime promotion. No model-backed release evaluation was rerun and no default agent profile was promoted.

## Changes

- Run control: the skill documents `pas runs`, `pas stop`, `pas kill`, `pas answer` and `pas monitor`, and the `--json` flags.
- Locks and exit codes: exit 5 means the pipeline is already running. Exit 6 means another Run holds the worktree. `--allow-shared-workdir` overrides only the worktree lock.
- Providers: `pi` is a fourth runtime provider and needs `llm_model` as `provider/model[:thinking]`. Every provider-consuming node must name `llm_provider`, or `pas validate` blocks with `provider_required`.
- Bounds: `allowed_tools` and node `max_budget_usd` apply to Claude and pi only. Codex and Gemini reject them. `reasoning_effort` and other unsupported attributes are rejected.
- Per-run resources: `--codergen-skill`, `[codergen] skills` and `[codergen.pi]` are documented.

## Known limitations

- The installed `pas` must be 0.11.1. Version 0.11.0 lacks pi, `stop`, `kill`, `answer`, `monitor` and the new `--plan` and `--json` flags.
- Codex and Gemini still run in YOLO mode. Use a disposable worktree.
