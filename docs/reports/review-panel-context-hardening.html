Engineering change brief · review-panel

From context-hungry loop to bounded, restartable review

Claude Code sessions showed that the review-panel workflow was consuming its parent context until repeated compaction—and sometimes prompt-length failure. The workflow was redesigned around bounded manifests, filesystem artifacts, hard limits, and one-shot fresh-session checkpoints.

Why this work was necessary

Session analysis found a strong association between exact review-panel invocations and repeated compaction. Two captured runs exceeded Claude Code's 200,000-token prompt maximum.

80%Exact review-panel sessions that compacted (8 of 10)
70%Exact invocations with repeated compaction (7 of 10)
60%Exact invocations with at least five compactions (6 of 10)
22.9%Non-review control sessions that compacted (760-session cohort)

Observed hard failures: 208,537 > 200,000 tokens and 241,686 > 200,000 tokens.

Architecture change

The parent orchestrator now coordinates paths, hashes, counts, and statuses. Detailed content lives in disposable worker contexts and workspace artifacts.

Before: accumulating parent

  • Raw diffs and per-file stats entered the parent context.
  • Seat reports and validator reasoning accumulated across stages.
  • Dirty rounds continued in the same conversation.
  • Inline fallbacks reintroduced bulky data when tooling failed.
  • Late checkpoints could not reliably reconstruct progress.
→

After: artifact-driven parent

  • Workers read diff content by path in disposable contexts.
  • Every stage returns a bounded manifest; details stay on disk.
  • Every continuing dirty round checkpoints and stops.
  • Packaging or subagent failure stops closed—no inline fallback.
  • Resume is hash-bound, one-shot, and requires a fresh session.

What changed

The fix is a contract redesign, not a bigger-context workaround.

01

Bounded preflight

  • A disposable resolver writes scope.json.
  • Targets over 25 files or 1,500 changed lines fail before CAST.
  • The parent never captures per-file stat output.
02

Artifact-only stage handoffs

  • CAST, SPAWN, MERGE, VALIDATE, FIX, and RE-REVIEW persist detailed outputs.
  • Parent-visible stage manifests are capped at 2 KiB.
  • Raw findings, reasoning, and diff content never return to the parent.
03

Finite fan-out

  • At most eight seats, including two supplementary seats.
  • Agent-type discovery is capped and truncation is disclosed.
  • Validation is capped after Critical multipliers are applied.
04

Fresh-session convergence

  • Every continuing dirty full-mode round writes a checkpoint and stops.
  • Checkpoint state references hashed progress, cast, sovereignty, and diff artifacts.
  • The next round launches via a new claude -p process.
05

Replay-resistant resume

  • --resume requires an externally emitted SHA-256.
  • Checkpoint bytes are verified before parsing.
  • Atomic claims keyed by content hash reject replay, copies, hard links, and mutation.
06

Fail-closed terminal output

  • Unknown or malformed statuses fail automation.
  • Skipped fixes remain unresolved; ordinary findings cannot hide under escalation.
  • Final parent output is generated from a bounded synthesis summary.
07

Session identity hook

  • A standalone plugin SessionStart hook exposes the Claude session ID.
  • Resume rejects the checkpoint's originating session.
  • Plugin inspection now reports one registered hook instead of zero.
08

Mechanical regression contracts

  • Context-budget behavior is asserted in dedicated tests.
  • Checkpoint claiming is black-box tested.
  • Standalone hook packaging and identity behavior are verified.

Enforced context budget

These are hard boundaries. Exceeding one produces an explicit stop or scope error rather than quietly spending more context.

Release and upgrade

This work ships as Review Panel 1.0.0 inside scott-cc 5.7.0. Existing installations must update and restart Claude Code before new sessions use the bounded orchestration contract:

  1. Update the installed plugin.
  2. Restart Claude Code.
  3. Confirm new sessions load the updated version and hook.
  4. Split review targets that exceed the new hard scope gate.
  5. Run emitted checkpoint continuation commands as fresh processes.

Breaking behavior: inline fallbacks and same-conversation convergence loops are intentionally rejected.
