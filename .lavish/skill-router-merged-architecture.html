01 / Shared system & ownership

The policy engine is outside either agent

Hermes calls the native adapter through a Python callback, not HTTP. The portable package selects IDs. The host authorizes and serves content. A future Claude adapter can reuse the selector, but cannot inherit Hermes’s lifecycle, receipts or provider-accounting powers merely by importing it.

Latest unmerged host seamImplemented portable packageOlder candidate to re-portProposed / absent

Click or keyboard-activate a node for exact behavior and evidence. On small screens, pan horizontally; diagrams keep readable text instead of shrinking labels.

Two registries, one checked translation

The plugin’s explicit-root registry provides qualified policy IDs and routing metadata. Hermes’s own skills_list() supplies eligible public catalog IDs. The adapter translates portable selections to host names; unavailable or duplicate translations fail the whole decision. This is an explicit reconciliation boundary—not an automatic shared catalog.

Not a process isolation sandbox

The seam minimizes the callback value object; the native plugin still runs trusted Python in the host process and can read its declared roots. Neither a routing receipt nor an allowlist means arbitrary plugin code is sandboxed. Operator trust and skill-content trust remain separate decisions.

Design contract ≠ current extracted implementation

The original plan’s 2000 ms classifier goal, first-57 legacy text, session-keyed query/classifier LRUs, attested-external legacy lane and typed ingress closure must not be presented as shipped extraction behavior. Current source uses a 15000 ms classifier ceiling; portable legacy text can retain 1024 characters; untrusted portable records do not auto-route; the native registry is built at registration; and no query/classifier LRU is wired here. The selector accepts a caller-supplied cached classifier result, but that parameter is not a cache service.

Also, “bounded top-k” bounds returned candidates and classifier work, not inventory scan cost: structured documents/frequencies and hash vectors are built across eligible records during a route. Registry compilation reads whole skill files. Resource hashing in the older full host additionally reads recursive linked files for all catalog entries.

03 / Hermes integration & runtime

One decision before the first model request

run_conversation establishes a turn-scoped contextvar, then turn_context routes after user normalization and before prompt restoration/build. The selected set holds across every model/tool iteration in that turn. A finally block restores the caller’s scope.

  1. Register once. PluginContext.register_skill_router accepts one exclusive protocol/callback pair. Disposal or unload releases the slot. The standalone plugin tries v2; latest Slice 1 rejects it and accepts v1.
  2. Minimize the request. Current semantic text only. Host strips inline image/file hints and excludes binary attachment parts. V1 reports has_attachments; richer fixed facts require the older v2 candidate.
  3. Deny before discovery and callback. A registered router has empty authorization while pending. Catalog error, timeout, malformed result, unknown ID or reentrant skill access stays denied. No registered router retains ordinary Hermes behavior.
  4. Preserve cached prompt bytes. Current directive is stamped in current-user API content. The Codex app-server branch composes the same directive into its input. It supersedes stale historical route directives; it does not mutate the cached prefix each turn.
  5. Load only on demand. Latest Slice 1 checks the requested name at skill_view. The older candidate adds final resolved source/generation/digest verification for bodies and linked resources.
  6. Close the turn. Authorization is reset even on errors/interruption. Older candidate additionally exports durable receipt and settles the shared physical request budget. Those guarantees are not in latest PR #17.

Older-host / no-seam fallback is deliberately weaker

If the public seam is unavailable—or the plugin’s explicit registry is empty—the plugin installs advisory pre_llm_call context and pre_tool_call blocking instead. Fallback decisions are keyed by session and turn; missing correlation blocks skill_view. Hooks cannot suppress core inventory, own prompt assembly, pre-load bodies or establish complete authoritative parity. Empty configured roots therefore do not mean “an authoritative empty selection for every host skill.”

05 / Trust, budgets, prompt cache & content

Keep selection, local reads and model exposure distinct

Trust boundary

  • Skills may declare data, aliases and addressable policy keys—not their own trusted roots or active repository authority.
  • Only operator-trusted policy plus an operation can require a skill. Tracker files alone do not activate it.
  • The portable/native registry and Hermes eligible catalog must reconcile. Neither the v1 request nor canonical-name translation carries a metadata-content hash across that boundary.
  • A selected skill’s instructions remain third-party content. Routing authorization is not permission to override user or system instructions.

Budget boundary

  • Candidate/selection caps bound routing output; they do not cap every local body/link read.
  • Classifier token, latency and cost validation is distinct from the full host’s physical dispatch ceiling.
  • Body/context budgets are the existing host’s responsibility. The target does not inherit every deferred_budget preload behavior from the historical design.
  • Callback deadlines are host lifecycle settings; a zero setting disables the deadline. A classifier’s 15-second ceiling does not override a shorter host callback timeout.

Prompt-cache boundary

  • Per-turn selected identities live after the cached static prefix, in current-user wire content or Codex input.
  • Latest Slice 1 keeps existing inventory assembly. Inventory suppression is a separate older-host feature.
  • The full candidate freezes session prompt mode. New authoritative sessions get a constant protocol; restored legacy sessions need explicit migration semantics.
  • Static prompt stability is not automatic registry/query/classifier-cache invalidation.

Receipt / privacy boundary

  • Do not conflate path-free portable routing diagnostics with the host authorization receipt, which stores resource descriptors containing local identities/paths.
  • Current response v2 produces signed receipt v3. Local HMAC does not mean remote attestation.
  • Unsigned v1/v2 compatibility receipts are still accepted. An upstream migration policy is required.
  • Classifier fields exclude bodies/paths by shape, but intent text may contain private user text. No provider call was made for this brief.
