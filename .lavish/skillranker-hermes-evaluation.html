Architecture decision brief · Hermes skill routing

Borrow the guardrails.
Do not adopt the router.

SkillRanker has several sharp defensive ideas, but its TypeSafe-first, two-call architecture conflicts with the local-first Hermes router we are designing. The right move is to preserve Hermes, import a few independently expressed contracts, and gate any Jev experiment behind written permission and a private benchmark.

The systems share a problem, not an architecture

Both systems want to stop an agent from guessing from a thin skill index. SkillRanker asks Jev to do broad semantic ranking, then a detailed rerank. Hermes first resolves authority and local evidence, reserving one provider call for a small gray zone.

Why Hermes is the better foundation

The model is not allowed to overrule known authority or compensate for missing evidence by guessing.

  • Exact means exact: attachments, explicit IDs, and trusted policy bypass classification.
  • Local evidence is mandatory: BM25 always runs; embeddings are optional and local.
  • Ambiguity is a predicate: not a synonym for “a model might help.”
  • Composition matters: Hermes can select up to three complementary skills and reject conflicts.
  • Failure is restraint: timeout, malformed output, or unknown cost does not broaden routing.

Concrete behavior comparison

SkillRanker’s engineering discipline is real. The mismatch is that its model sits at the center of implicit routing, while Hermes treats a model as an optional tie-breaker.

Ideal use cases

There is a legitimate home for each shape. The mistake would be treating a TypeSafe-first advisory router as a drop-in implementation of Hermes’s policy-aware runtime.

Hermes hybrid router

Default foundation
  • Default routing inside Hermes.
  • Exact requests and authoritative project policy.
  • Privacy-sensitive repositories and offline/degraded operation.
  • Zero-to-three skill composition with conflicts.
  • Auditable receipts and outcome calibration.

Native Jev ambiguity lane

Conditional experiment
  • Two to five genuinely plausible candidates.
  • One request with a Choice plus independent fit questions.
  • Opaque IDs and approved metadata only.
  • Private synthetic benchmark before any canary.
  • Explicit opt-in; never enabled by key presence.

SkillRanker

Standalone niche
  • TypeSafe-first agents with explicit disclosure consent.
  • Manual or shadow ranking over a large roster.
  • Single-skill recommendation where two calls are acceptable.
  • Research on wide semantic ranking and near-miss rejection.
  • Not Hermes’s default turn-critical path.

The immediate blocker is permission, not engineering

Engineering risk assessment · not legal advice. Possessing a TypeSafe API key does not authorize SkillRanker use or a third-party Hermes integration.

SkillRanker license rider

The reviewed license withholds rights from OpenAI, Anthropic, affiliates, and people or entities acting for their benefit. Its definition of “use” expressly includes analysis, execution, testing, benchmarking, indexing, and incorporation.[2] In this OpenAI-hosted agent context, that is a hard stop absent explicit written permission.

TypeSafe preview terms

The current public terms limit API use to evaluation, prohibit providing products or services to third parties, prohibit development of similar or competing products, and prohibit publishing benchmarks or performance information.[5] A production Hermes backend and a public comparison both require written clarification or amended terms.

Privacy is not zero retention

TypeSafe says it does not train or fine-tune models on input, but its policy permits collecting prompts, processing and improving services, disclosure to service providers, and retention for as long as reasonably necessary.[6] Start with synthetic prompts even after evaluation permission is obtained.

If clearance arrives: test one narrow hypothesis

The hypothesis is not “Jev can rank skills.” TypeSafe already publishes evidence that a two-call suggestion can reduce wrong and needless loads on a synthetic Hermes benchmark.[8] The useful question is whether one sanitized Jev call improves only the ambiguous cases that Hermes local retrieval cannot confidently resolve.

Promotion is intentionally hard

  • 100% exact and trusted-policy route accuracy.
  • Zero provider calls outside frozen ambiguity.
  • Zero prompt, body, path, secret, repository, or tool-output disclosure.
  • ≤ 1 provider request per ambiguous turn.
  • ≥ 95% positive-family recall and negative-family restraint.
  • Strictly better ambiguous-case quality at equal provider-call budget.
  • ≤ 2,000 ms classifier p95.
  • Zero infrastructure errors in the frozen final run.

Pin jev-1.13.0 for each stratum. TypeSafe warns that aliases move and answers may change; returned model identity must be recorded.[7]

What Hermes should borrow now

These are general defensive contracts, expressed in Hermes’s own architecture. They do not require a runtime dependency.

01

Opaque provider handles

Bind provider-facing IDs locally. Never let names, paths, or option text become authority.

02

Exact response sets

Reject missing, unknown, duplicate, out-of-range, or non-normalized answers as one invalid classifier result.

03

Layered abstention

Separate global need, candidate fit, score and margin, eligibility, and conflict checks.

04

Typed outcomes

Distinguish selected, abstain, unavailable, and error without storing content-bearing rationale.

05

Versioned model identity

Moving aliases cannot share thresholds or calibration strata with a pinned model revision.

06

Capability discovery

Integrations should query implemented capabilities instead of inferring them from version numbers or README prose.

07

Robustness permutations

Test option order, opaque-ID renaming, decoys, near-duplicates, malformed outputs, and hostile metadata.

08

Scores are not outcomes

Provider confidence and rank softmax weights remain uncalibrated until tied to actual Hermes usefulness data.
