The thesis

Issue modeling is already above average: strong acceptance criteria, dependencies, evidence notes, and close reasons. The missing layer is a fail-closed lifecycle around that good data.

From optional bookkeeping to an owning-work contract

Today, sessions often inspect Beads but do not mechanically prove ownership or completion. The target workflow makes every state transition explicit.

Observed pattern

  • Run bd prime or bd show.
  • Perform substantial implementation or operational work.
  • Sometimes update notes or close; sometimes stop at a prose summary.
  • Application tests run, but Beads preflight does not.
  • Schema bypasses survive beyond their recovery window.
→

Recommended contract

  • Discover one owning bead and inspect its scope.
  • Atomically claim or confirm ownership before work.
  • Append bounded evidence and remaining risks.
  • Run a project-owned Beads lifecycle verifier.
  • Close, defer, or leave a resumable checkpoint—never ambiguous limbo.

Recommended changes

Prioritized by expected impact. Use the filters to narrow the review; every card can be annotated directly in Lavish.

Show:
01

Bind every durable engineering session to one bead

P1 · lifecycle
Of 27 Beads-using sessions, 20 showed issues but only 8 explicitly claimed one. Existing in-progress state may explain some cases, but ownership was not mechanically asserted.

Action: Standardize prime → search → show → claim at session start.

02

Add a project-aware lifecycle gate

P1 · lifecycle
The built-in bd preflight --check is not a generic project gate: in this Python repository it incorrectly invokes Go tests, golangci-lint, gofmt, go.sum, and Beads CLI version checks.

Action: Build a scott-cc lifecycle verifier that checks issue binding, status, schema-bypass absence, decision labels, and the repository's real quality commands.

03

Expire schema-recovery bypasses

P1 · safety
Nine sessions used BD_IGNORE_SCHEMA_SKEW=1 or --ignore-schema-skew. A recovery session later proved all canonical workspaces passed normal status, yet bypass use continued.

Action: Allow bypass only inside a bounded recovery procedure; reject it in normal workflows afterward.

04

Create beads for durable repository and service changes

P1 · coverage
The skill-cabinet session changed inc-prod configuration, Homebrew state, a managed service, an alias, and the port registry—but only ran bd prime.

Action: If work changes a repository, deployment, managed service, or durable machine configuration, require an owning bead.

05

Surface decision beads through the human queue

P2 · discoverability
Current decision issues scc-pjk and scc-i2w correctly await Scott, but lack the human label and therefore do not appear in bd human list.

Action: Label human-blocked decisions human; keep them unclaimed until answered.

06

Prefer append-only, structured checkpoints

P2 · evidence
Mutation and migration sessions recorded excellent evidence, but sometimes embedded large reports directly in --notes.

Action: Use --append-notes, artifact paths/hashes, --external-ref, and --await-id where applicable.

07

Use project memory for reusable operating knowledge

P2 · continuity
No reviewed session used bd remember, despite several reusable lessons: mutation-worktree placement, Dolt recovery invariants, and project-specific migration verification rules.

Action: Save stable cross-issue facts only—not temporary status or task progress.

08

Make repository selection explicit

P2 · correctness
Sixteen Beads-using sessions had no persisted session workspace. Tool-level workdirs often saved them, but compaction or a bare command could target the wrong database.

Action: Start inside the owning repository and use bd -C /absolute/repo/path … in scripts and delegated work.

Keep these behaviors

The review is not an argument for more ceremony. These are already strong and should remain untouched.

Acceptance criteria are concrete

Major epics usually define measurable outcomes, boundary behavior, dependencies, and explicit exclusions.

Close reasons carry evidence

Ten of eleven closing sessions recorded a reason; release and mutation work frequently included exact verification results.

Dependencies model real ordering

Mutation-testing and RAG epics used parent-child structure and blocker edges rather than flat issue piles.

Delegated workers do not mutate project state

Across 262 related child sessions, no Beads writes were detected. Keep lifecycle ownership in the parent.
